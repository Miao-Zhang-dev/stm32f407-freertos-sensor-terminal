# STM32F407 FreeRTOS sensor terminal

This project contains the portable application core for a four-task sensor terminal. It is organized for integration into an STM32CubeIDE project generated for an STM32F407. The workspace did not include a board schematic or a CubeMX project, so board pin assignments and peripheral handles are supplied by the application port.

## Project contents

- `Core/Src/terminal.c`: measurement validity, default thresholds, and alarm evaluation.
- `Core/Src/modbus_rtu.c`: Modbus-RTU slave CRC, register access, exception responses, and validated threshold writes.
- `Core/Src/app_tasks.c`: acquisition, communications, storage, and alarm FreeRTOS tasks. A queue transfers samples to storage; a mutex protects the current sample and thresholds.
- `Core/Inc/app_port.h`: hardware adaptation contract for ADC/I2C acquisition, SPI Flash plus FATFS logging, UART/RS-485 transport, and alarm outputs.
- `Core/Src/board_port.c`: application adapter joining the SHT3x, ADC, FATFS, alarm, and Modbus callbacks.
- `Drivers/Src/sht3x.c`: callback-based SHT30/SHT31 single-shot measurement and CRC validation.
- `Drivers/Src/w25qxx.c`: callback-based W25Q-series SPI NOR read, page program, and sector erase driver.
- `Drivers/Src/w25q_fatfs_diskio.c`: 512-byte FatFs disk I/O adapter over 4 KB NOR erase sectors.
- `Drivers/Src/storage_fatfs.c`: FATFS CSV logging with header creation, append, and sync.
- `tests/test_core.c`: host-side examples for the portable application core.

## Hardware port

Implement the callbacks in `app_board_port_t` using the handles generated by CubeMX, then call `app_board_port_bind` before creating the tasks. The sensor callback reads the ADC; the built-in board adapter reads temperature and humidity through `sht3x_read_measurement`, logs through `storage_fatfs_append`, and forwards alarm and UART/RS-485 operations to the board callbacks.

Configure the chosen STM32F407 package, clocks, ADC/DMA, I2C, SPI, UART, RS-485 direction GPIO, FreeRTOS, and FATFS in CubeMX. Add `Core/Inc` and `Drivers/Inc` to the include path and compile the application and driver sources with the generated firmware. Initialize the SHT3x and W25Qxx callback contexts, bind the Flash callbacks into the FatFs disk driver table for drive 0, mount the volume with `storage_fatfs_mount`, then bind `app_board_port_t` with `app_board_port_bind`. Call `app_tasks_create()` before starting the scheduler. Implement the UART callbacks so receive returns exactly one complete RTU frame and send asserts/deasserts the RS-485 direction pin around transmission. The communication task retries a failed response transmission up to three times; a Modbus master should retry requests that receive no response or a CRC error.

The W25Q-to-FatFs adapter uses read/erase/rewrite for each 512-byte logical sector update because the Flash erase unit is 4 KB. It is intended for a small logging volume; it does not provide wear leveling or power-loss journaling.

The core uses C99. Temperature values are signed hundredths of a degree Celsius; humidity is hundredths of a percent; the ADC value is the raw 12-bit conversion. Invalid sensor values must have their corresponding validity bit cleared.

## Modbus register map

The default slave address is `1`. Multi-byte register values use Modbus big-endian byte order. Signed temperatures use two's-complement `int16` representation in hundredths of a degree Celsius.

| Table | Address | Meaning | Access |
|---|---:|---|---|
| Input | 0 | Air-quality ADC raw value | Read |
| Input | 1 | Temperature, 0.01 °C | Read |
| Input | 2 | Relative humidity, 0.01% | Read |
| Input | 3 | Validity flags: bit 0 air quality, bit 1 temperature, bit 2 humidity | Read |
| Input | 4-5 | Sample tick timestamp, high word then low word | Read |
| Input | 6 | Alarm flags: bit 0 air high, bit 1 temperature low, bit 2 temperature high, bit 3 humidity high | Read |
| Holding | 0 | Air-quality high threshold, raw ADC counts | Read/write |
| Holding | 1 | Temperature low threshold, 0.01 °C | Read/write |
| Holding | 2 | Temperature high threshold, 0.01 °C | Read/write |
| Holding | 3 | Humidity high threshold, 0.01% | Read/write |

Implemented functions are `0x03` Read Holding Registers, `0x04` Read Input Registers, `0x06` Write Single Register, and `0x10` Write Multiple Registers. Threshold writes are applied atomically only when the complete threshold set is valid. CRC errors, frames for other addresses, and malformed frames are ignored. UART framing timeout and retry timing belong to the board transport layer.

Default thresholds are ADC 2000, 0.00 °C low, 40.00 °C high, and 80.00% humidity high. Their allowed ranges follow the validation in `terminal_thresholds_valid`.
